# B 端货运稳定性与长期开发路线

## 近期目标

先稳定 B 端货运主链路，再扩展调度能力。当前两种业务模式共用同一条流程：

- `enterprise_terminal`：企业到终端点配送
- `community_group_buy`：企业到社区团长配送

## 已固化的数据契约

- `businessMode`: `enterprise_terminal | community_group_buy`
- `pointType`: `terminal | community_leader`
- `vehicle_source`: `internal | external | mixed`
- `external_demand_id`: 企业需求关联接单大厅公共需求
- `vehicle_allocation.vehicle_ids`: 实际分配车辆列表

后端仍兼容旧值 `vehicle_source = own`，读取时归一为 `internal`。

## Bug 修复优先级

- P0：回归 B 端外部需求联动、取消联动、接单车辆校验、schema 漏字段。
- P1：统一车辆状态机。企业调度分车后车辆进入 `in_transit`，配送完成或取消后释放回 `idle`。
- P1：统一 B 端业务字段。发布、调度、接单大厅、详情页展示同一套模式字段。
- P1：统一前端接口解包。企业端页面不直接假设 `res.data` 是业务对象。
- P2：维护数据库稳定性。增加调度相关索引，并提供旧数据关联回填脚本。
- P2：持续清理跨端 UI 规范问题，优先处理企业端主链路页面。

## 长期路线

1. B 端货运闭环：企业资料、点位管理、车队管理、发布配送、调度分车、配送点状态、完成确认。
2. 多角色协作：企业管理员、调度员、财务/结算、运力方、平台运营权限拆分，增加操作日志和通知。
3. 智能调度：多点排序、容量匹配、时间窗、冷链/车型约束，支持自动分配与人工调整。
4. 车机实时运输：车辆位置、电量、在线状态、任务状态、异常上报、轨迹和 ETA。
5. 结算与运营：企业账单、外部运力结算、对账报表、后台审核、异常订单处理。

## 回归清单

- 企业发布终端配送，自有车辆调度，配送点逐个完成。
- 企业发布社区团购配送，外部运力接单，车辆进入运输中。
- 企业取消待调度外部需求，接单大厅公共需求同步取消。
- 非本企业车辆、非外部运力车辆、运输中车辆接单均失败。
- 企业需求完成或取消后，已分配车辆恢复空闲。
