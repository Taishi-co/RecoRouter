# 社区团购营销 Agent 三臂模拟实验

> **重要声明：以下全部结果来自固定参数的 Monte Carlo 模拟，不是客户实绩，不是收益承诺，也不能代替客户自己的随机对照试验。**

- 模拟版本：1.0.0
- 固定随机种子：20260801
- Monte Carlo 次数：50,000
- 实验周期：28 天

## 1. 实验问题

在相同市场环境和用户规模下，对比三种经营方式：

1. **现状对照：**维持当前商品、触达和权益策略；
2. **人工营销：**由运营按经验统一选品、圈人、发券和搭活动；
3. **Agent 营销：**由 Agent 在库存、毛利、预算和频控约束下联合优化，所有执行动作仍经人工审批。

模拟回答的是：在这些透明假设成立时，三组的增量付费用户、订单、GMV 和 ROI 可能落在哪个范围。它不能证明 Agent 已经在真实客户中产生这些收益。

## 2. 实验设计

- 随机化单位：社区簇，降低同一微信群、团长或自提点之间的信息污染；
- 每臂 300 个社区，平均每社区 180 名合规可触达用户；
- 每臂约 54,000 人，三臂合计约 162,000 人；
- 社区规模变异系数 25%；
- 付费转化率组内相关系数 ICC = 0.018，订单 ICC = 0.012；
- 每轮同时抽取市场基线、社区簇抽样误差、策略响应、客单价和成本波动；
- 所有增量指标均以当轮同期对照组按用户规模归一后计算。

## 3. 透明假设

### 3.1 基线经营假设

| 参数 | 中心值 | 每轮不确定性 | 说明 |
|---|---:|---:|---|
| 28 天付费转化率 | 9.0% | 标准差 0.50pp | 需要用客户历史数据替换 |
| 每付费用户订单数 | 1.24 | 标准差 0.03 | 同一周期内复购 |
| 平均客单价 | ¥51 | 标准差 ¥2 | 每轮共同市场波动 |
| 贡献毛利率 | 21.5% | 标准差 1.2% | 商品收入扣除采购、履约等变动成本，尚未扣本次营销成本 |

### 3.2 策略效果与成本假设

| 参数 | 人工营销 | Agent 营销 | 采用理由与边界 |
|---|---:|---:|---|
| 付费转化相对提升 | 均值 9.0%，标准差 4.0% | 均值 18.0%，标准差 5.5% | 是待验证先验，不是已实现效果；Agent 假设受益于选品、人群、权益和会场联合优化 |
| 每付费用户订单数相对提升 | 2.5% | 5.5% | 反映组合购与复购，不计 28 天后的长期价值 |
| 客单价相对变化 | -0.4% | -0.2% | 考虑优惠导致的轻微稀释，不假设客单价暴涨 |
| 被定向用户比例 | 22.0% | 16.0% | Agent 用更窄人群减少自然订单补贴 |
| 定向人群核销率 | 5.5% | 6.0% | 只用于估算补贴成本，核销本身不是成功指标 |
| 单次核销补贴 | ¥4.20 | ¥3.80 | 由平台承担的平均权益成本 |
| 试点固定成本 | ¥5,000 | ¥7,500 | 人工含策划/搭建；Agent 含平台、推理、监控及人工审批成本 |
| 单个定向用户渠道成本 | ¥0.035 | ¥0.025 | 短信、素材分摊或团长触达等变动成本 |

Agent 的先验值有意保持在可被真实 A/B 测试证伪的范围，没有假设转化翻倍、零成本获客或无限库存。正式售前应先用客户近 8—12 周基线替换本表，再运行脚本。

## 4. 结果

| 实验臂 | 付费转化率 | 增量付费用户 | 增量订单 | 增量 GMV | 每增量付费用户成本 | ROI | 正 ROI 概率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 现状对照 | 9.00%（P10 8.28% / P90 9.71%） | 0（P10 0 / P90 0） | 0（P10 0 / P90 0） | ¥0（P10 ¥0 / P90 ¥0） | —（P10 — / P90 —） | —（P10 — / P90 —） | — |
| 人工营销 | 9.80%（P10 8.92% / P90 10.72%） | 434（P10 80 / P90 794） | 700（P10 153 / P90 1,262） | ¥34,195（P10 ¥6,036 / P90 ¥63,471） | ¥18（P10 ¥10 / P90 ¥54） | -10.2%（P10 -84.0% / P90 71.2%） | 43.4% |
| Agent 营销 | 10.61%（P10 9.59% / P90 11.68%） | 872（P10 448 / P90 1,314） | 1,468（P10 815 / P90 2,157） | ¥73,906（P10 ¥40,437 / P90 ¥109,643） | ¥11（P10 ¥7 / P90 ¥22） | 63.6%（P10 -11.6% / P90 150.2%） | 86.0% |

其中：

- ROI =（增量 GMV × 贡献毛利率 − 本次活动总成本）÷ 本次活动总成本；
- 增量付费用户成本也可称增量 CAC；仅在当轮增量付费用户大于 0 时计算；
- 对照组没有本次增量营销成本，因此 ROI、增量 CAC 和正 ROI 概率不适用；
- 增量付费用户、增量订单和增量 GMV 允许在低分位为负，这是实验风险，不应隐藏。

## 5. Agent 相对人工营销的模拟差异

按各自 P50 做描述性比较：

- 付费转化率高 0.81pp；
- 增量付费用户多约 438 人；
- 增量订单多约 768 单；
- 增量 GMV 多约 ¥39,710；
- ROI 高约 73.82pp。

这组差异来自脚本中的效果先验，不是 Agent 的固有属性。真实试点如果没有足够的数据质量、库存、履约能力、触达授权或运营审批，结果可能显著更差。

## 6. 如何用于客户试点

1. 用客户自己的社区规模、历史转化、客单价、贡献毛利、券成本和履约成本替换默认参数；
2. 先锁定一项主指标，例如“每社区 28 天增量贡献利润”，其他指标作为护栏；
3. 按社区/团长簇随机分配三臂，避免同群用户交叉污染；
4. 实验期间固定统计口径，记录缺货、退款、投诉、取消关注和履约超时；
5. 预先声明停止规则，不因中途数据好看而提前结束；
6. 最终用真实对照差异替换模拟先验，并按社区分层报告不确定性。

## 7. 模型未覆盖的风险

- 团长跨社区传播、用户跨社区下单等网络干扰；
- 极端天气、节假日、竞品补贴和供应中断；
- SKU 级缺货替代、退款、售后和 28 天后的留存价值；
- 不同社区、人群和商品之间更复杂的异质性；
- 模型上线后的策略漂移、人工审批延迟及执行偏差。

因此，本模拟适合做售前价值量级讨论、试点预算和实验设计，不适合单独作为采购回报承诺。

## 8. 复现

在项目根目录运行：

```bash
node scripts/simulate-community-marketing-agent.mjs
```

脚本不依赖第三方包，固定使用随机种子 20260801，将覆盖生成：

- `docs/data/community-marketing-agent-simulation.json`
- `docs/community-marketing-agent-simulation.md`

在 Node.js 版本和脚本内容不变时，重复运行结果应完全一致。
