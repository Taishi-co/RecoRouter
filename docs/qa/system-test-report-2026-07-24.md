# RecoRouter 商城与管理端系统测试记录

测试日期：2026-07-24

测试范围：商城 H5/模拟小程序、Web 管理端、商城 API、账号与隐私合规、基础性能

线上环境：

- 商城：https://car.shcxyz.site:18082/
- 管理端：https://car.shcxyz.site/
- API：https://car.shcxyz.site/api/

## 1. 测试结论

本轮共整理 33 个核心测试用例，覆盖公开浏览、登录鉴权、数据归属、隐私撤回、账号注销、发票、商家资质、客服投诉、管理端保护和性能。

代码基线校验、Rust 测试框架、真实浏览器公开流程及线上公开接口性能采样均通过。专项审计发现 4 个需要修复的问题，均已在本分支修复并补充自动检查：

1. 撤回隐私同意后，已有登录令牌仍可继续调用商城业务接口。
2. 老用户缺少服务端同意记录时，小程序只看本地状态，不会重新提示。
3. 注销申请的阻塞事项清除后不会自动完成，需要用户取消后重新申请。
4. 注销只清理用户主表和少量临时数据，历史订单中的收货人、电话、地址、定位等直接身份信息仍未匿名化，集采款项和处理中发票也未纳入阻塞。

## 3. 缺陷与改进记录

| 缺陷 | 等级 | 现象 | 处理 |
| --- | --- | --- | --- |
| BUG-01 | P0 | 撤回隐私同意后业务令牌仍可用 | 新增服务端商城隐私守卫；隐私与注销接口独立保留 |
| BUG-02 | P1 | 老会话只有本地同意状态，服务端没有证据 | 启动时读取服务端最新同意记录和当前政策版本 |
| BUG-03 | P1 | waiting 注销不会随阻塞项清除自动完成 | 查询注销状态时重新计算阻塞项并自动完成 |
| BUG-04 | P0 | 注销后订单直接身份信息、客服关联等仍可识别 | 保留法定交易结构，匿名化收货与定位数据，清理临时权益和自提码 |
| IMP-01 | P2 | 每次商城鉴权若分别查会话和隐私会增加数据库往返 | 合并为单条会话与最新同意状态查询 |
| IMP-02 | P2 | 缺少可重复执行的上线合规回归 | 新增静态门禁、数据库集成用例和显式授权的生产 E2E 脚本 |

## 4. 性能采样

线上公开 API 低强度采样参数：3 并发、5 秒、247 次请求。

| 接口 | 请求数 | p50 | p95 | 错误/5xx |
| --- | ---: | ---: | ---: | ---: |
| `/api/health` | 62 | 15.04 ms | 18.19 ms | 0 |
| `/api/mall/categories` | 62 | 15.99 ms | 21.40 ms | 0 |
| `/api/mall/products?page=1&pageSize=20` | 62 | 59.09 ms | 107.57 ms | 0 |
| `/api/mall/legal-center` | 61 | 17.83 ms | 25.84 ms | 0 |
| 总体 | 247 | 17.67 ms | 72.20 ms | 0 |

首批连接出现约 2.5 秒的 p99 尖峰，但持续请求的 p95 正常，判断更接近 TLS/连接冷启动而不是持续数据库瓶颈。商城前端已对商品、分类、首页配置等 GET 请求做短缓存与并发合并。

## 5. 自动化执行说明

常规本地回归：

```bash
pnpm validate
pnpm validate:split
cargo test --manifest-path server/Cargo.toml --workspace --lib --bins --tests
```

带独立 PostgreSQL 的数据库集成回归：

```bash
TEST_DATABASE_URL='postgres://...' pnpm test:rust-server:db
```

生产环境临时账号 E2E 会创建两个测试账号并在完成后立即注销，必须显式授权，不会随常规校验自动运行：

```bash
ALLOW_PRODUCTION_TEST=1 pnpm test:production:miniapp-compliance
```

当前本机未配置 `TEST_DATABASE_URL`，因此 Rust 测试框架可完成编译与非数据库用例，但数据库型用例会主动跳过；本轮以部署后的生产 E2E 补充验证真实数据库路径。
